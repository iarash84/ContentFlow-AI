# ContentFlow-AI

این پروژه یک سیستم خودکار برای دریافت خبر و محتوای فنی از فیدهای RSS/Atom و صفحه‌ی Trending گیت‌هاب است. سیستم، در صورت فعال بودن Gemini، برای هر مطلب عنوان، خلاصه و هشتگ تولید می‌کند و سپس پیام را به یک یا چند کانال تلگرام می‌فرستد.

این سیستم روی Google Apps Script اجرا می‌شود؛ بنابراین برای اجرای آن به خرید سرور یا نصب نرم‌افزار روی کامپیوتر نیاز ندارید. اطلاعات حساس، تنظیمات و تاریخچه‌ی انتشار در Script Properties همان پروژه ذخیره می‌شوند.

> این راهنما عمداً از صفر نوشته شده است. اگر با Google Apps Script، ربات تلگرام یا API آشنایی ندارید، مراحل را دقیقاً به ترتیب انجام دهید.

## نتیجه‌ای که در پایان خواهید داشت

در پایان راه‌اندازی:

1. یک پروژه در Google Apps Script دارید.
2. یک ربات تلگرام دارید که اجازه‌ی ارسال پیام در کانال را دارد.
3. یک کانال تلگرام برای دریافت پیام دارید.
4. کلید Gemini را در تنظیمات پروژه ثبت کرده‌اید؛ یا تصمیم گرفته‌اید سیستم بدون Gemini کار کند.
5. منابع خبری را تنظیم کرده‌اید.
6. ابتدا ارسال و دریافت را دستی آزمایش کرده‌اید.
7. یک Trigger ساعتی ساخته‌اید تا سیستم خودکار اجرا شود.

## پیش‌نیازها

این موارد را قبل از شروع آماده کنید:

- یک حساب Google شخصی یا کاری. این حساب مالک پروژه و اجراکننده‌ی اسکریپت خواهد بود.
- یک شماره تلفن فعال برای ساخت حساب تلگرام، اگر هنوز حساب تلگرام ندارید.
- یک کانال تلگرام که خودتان مالک آن هستید یا در آن Administrator هستید.
- یک ربات تلگرام که از طریق BotFather می‌سازید.
- یک کلید Gemini از Google AI Studio؛ استفاده از آن اختیاری است، اما برای تولید خلاصه و ترجمه توصیه می‌شود.
- یک آدرس RSS/Atom معتبر، اگر می‌خواهید منبع خبری اختصاصی اضافه کنید.

## مرحله‌ی صفر: آماده‌کردن حساب‌ها و دسترسی‌ها

### ۰.۱ ساخت یا آماده‌کردن حساب Google

1. اگر حساب Google دارید، به [صفحه‌ی Google Apps Script](https://script.google.com/) بروید و با همان حساب وارد شوید.
2. اگر حساب ندارید، در [صفحه‌ی ساخت حساب Google](https://accounts.google.com/signup) یک حساب بسازید.
3. حسابی را انتخاب کنید که همیشه به آن دسترسی دارید؛ چون Triggerهای زمان‌بندی‌شده با همین حساب اجرا می‌شوند.
4. اگر حساب سازمانی یا مدرسه‌ای دارید، ممکن است مدیر سازمان اجازه‌ی ساخت Apps Script یا استفاده از API را محدود کرده باشد. در این حالت از حساب شخصی Google استفاده کنید یا از مدیر سازمان اجازه بگیرید.

### ۰.۲ ساخت یا آماده‌کردن کانال تلگرام

اگر کانال ندارید:

1. تلگرام را در موبایل یا دسکتاپ باز کنید.
2. گزینه‌ی ساخت کانال جدید را انتخاب کنید. در نسخه‌های مختلف تلگرام این گزینه معمولاً از منوی **New Message → New Channel** یا علامت مداد در دسترس است.
3. یک نام و در صورت تمایل توضیح برای کانال وارد کنید.
4. نوع کانال را انتخاب کنید:
   - **Public**: یک نام کاربری مانند `@my_news_channel` دارد و پیدا کردن شناسه‌ی آن آسان‌تر است.
   - **Private**: فقط افراد دعوت‌شده آن را می‌بینند و برای تنظیم برنامه به شناسه‌ی عددی نیاز دارید.
5. ساخت کانال را تمام کنید و مطمئن شوید خودتان Administrator آن هستید.

اگر کانال از قبل وجود دارد، باید مالک یا Administrator دارای امکان افزودن Administrator باشید.

## مرحله‌ی ۱: ساخت ربات تلگرام

ربات همان حسابی است که پیام‌ها را منتشر می‌کند.

1. در تلگرام، جست‌وجو کنید: `@BotFather`.
2. دقت کنید حساب رسمی BotFather علامت تأیید داشته باشد؛ به حساب‌های مشابه اعتماد نکنید.
3. گفت‌وگو را باز کنید و دکمه‌ی **Start** را بزنید.
4. دستور `/newbot` را بفرستید.
5. BotFather یک نام نمایشی می‌خواهد؛ مثلاً `ContentFlow Publisher`.
6. سپس یک username می‌خواهد. username باید با `bot` تمام شود؛ مثلاً `contentflow_publisher_bot`.
7. BotFather پیامی شامل یک **HTTP API token** می‌فرستد. این رشته معمولاً شبیه نمونه‌ی زیر است:

   ```text
   123456789:AAExampleTokenValueDoNotUse
   ```

8. کل توکن را کپی و در جای امن موقت نگه دارید. این توکن مانند رمز عبور است؛ آن را در README، GitHub، اسکرین‌شات یا گفت‌وگوی عمومی قرار ندهید.
9. اگر توکن فاش شد، در BotFather از دستور `/revoke` استفاده کنید، ربات را انتخاب کنید و توکن جدید بگیرید. سپس مقدار قبلی را در Script Properties با توکن جدید جایگزین کنید.

### افزودن ربات به کانال

1. کانال خود را باز کنید.
2. به صفحه‌ی اطلاعات کانال بروید.
3. بخش **Administrators** را باز کنید.
4. گزینه‌ی افزودن Administrator را بزنید.
5. username رباتی را که ساختید جست‌وجو کنید و انتخاب کنید.
6. دست‌کم مجوز **Post Messages** یا «ارسال پیام» را فعال کنید.
7. ذخیره کنید.

برای جلوگیری از خطا، ربات را فقط به کانالی اضافه کنید که می‌خواهید همین سیستم در آن پیام منتشر کند.

## مرحله‌ی ۲: پیدا کردن شناسه‌ی کانال

### کانال عمومی

اگر کانال username عمومی دارد، همان username را با `@` در تنظیمات وارد کنید:

```text
@my_news_channel
```

حروف username را دقیقاً وارد کنید. فاصله و لینک کامل مانند `https://t.me/...` را وارد نکنید.

### کانال خصوصی یا زمانی که username کار نمی‌کند

برای کانال خصوصی، شناسه معمولاً یک عدد منفی است که با `-100` شروع می‌شود؛ مانند:

```text
-1001234567890
```

روش پیشنهادی برای پیدا کردن شناسه:

1. ربات را به کانال اضافه کنید و مجوز ارسال پیام بدهید.
2. در کانال یک پیام آزمایشی منتشر کنید.
3. پیام را به رباتی که برای مشاهده‌ی شناسه‌ی کانال استفاده می‌کنید forward کنید، یا از روش رسمی دریافت updateهای Telegram Bot API استفاده کنید.
4. در داده‌ی دریافتی، مقدار `chat.id` را پیدا کنید. همان مقدار، شناسه‌ی کانال است.
5. مقدار را بدون تغییر، شامل علامت منفی، در Script Properties ثبت کنید.

اگر از ربات‌های ناشناس برای پیدا کردن شناسه استفاده می‌کنید، پیام‌های خصوصی، توکن یا اطلاعات حساس را برای آن‌ها ارسال نکنید. برای کانال عمومی، استفاده از `@username` ساده‌تر و امن‌تر است.

## مرحله‌ی ۳: ساخت پروژه‌ی Google Apps Script

1. به [script.google.com](https://script.google.com/) بروید.
2. با حساب Google موردنظر وارد شوید.
3. روی **New project** کلیک کنید.
4. نام پروژه را از بالای صفحه، مثلاً به `ContentFlow-AI` تغییر دهید.
5. در ویرایشگر، فایل پیش‌فرض `Code.gs` را باز کنید.
6. محتوای کامل فایل [`Code.gs`](Code.gs) این مخزن را کپی کنید.
7. محتوای قبلی ویرایشگر را کامل حذف کنید و کد کپی‌شده را جایگزین کنید.
8. روی **Save project** یا آیکون ذخیره کلیک کنید.
9. اگر Google درباره‌ی نام پروژه یا ذخیره‌سازی پرسید، نام دلخواه را تأیید کنید.

فایل [`Code.gs`](Code.gs) شامل همه‌ی منطق دریافت منبع، تولید متن، تشخیص تکرار، ارسال تلگرام و زمان‌بندی است. به‌جز بخش [`PROMPTS`](Code.gs:5)، برای راه‌اندازی اولیه نیازی به تغییر کد ندارید.

## مرحله‌ی ۴: دریافت کلید Gemini

Gemini برای تولید متن فارسی، خلاصه و هشتگ استفاده می‌شود. این مرحله اختیاری است؛ بدون Gemini هم سیستم با متن خام منبع کار می‌کند.

1. به [Google AI Studio](https://aistudio.google.com/) بروید.
2. با همان حساب Google یا یک حساب Google دیگر وارد شوید.
3. اگر صفحه‌ی شرایط استفاده نمایش داده شد، آن را مطالعه و تأیید کنید.
4. در منوی سمت چپ یا بالای صفحه گزینه‌ی **Get API key** یا **Create API key** را پیدا کنید.
5. روی **Create API key** کلیک کنید.
6. اگر از شما خواسته شد، یک Google Cloud project انتخاب کنید یا گزینه‌ی ساخت پروژه‌ی جدید را بزنید. نامی مانند `ContentFlow-AI` انتخاب کنید.
7. ساخت کلید را تأیید کنید و کلید نمایش‌داده‌شده را کپی کنید.
8. کلید را در فایل، ایمیل، GitHub یا چت عمومی ذخیره نکنید؛ در مرحله‌ی بعد مستقیماً در Script Properties وارد می‌کنیم.

اگر Google از شما روش پرداخت یا فعال‌سازی صورتحساب خواست، محدودیت‌های حساب و منطقه را در [مستندات قیمت‌گذاری Gemini](https://ai.google.dev/gemini-api/docs/pricing) بررسی کنید. از سهمیه و هزینه‌ی حساب خود مطلع باشید و کلید را در اختیار دیگران نگذارید.

### اگر کلید Gemini نساختید

در این حالت مقدار `GEMINI_API_KEY` را ثبت نکنید و مقدار `ENABLE_AI_FALLBACK` را `true` بگذارید. سیستم در صورت نبودن یا خطای Gemini، عنوان و توضیح خام RSS را به پیام تبدیل می‌کند. کیفیت خلاصه و ترجمه در این حالت کمتر است، اما ارسال خودکار متوقف نمی‌شود.

## مرحله‌ی ۵: واردکردن تنظیمات در Script Properties

Script Properties محل امن تنظیمات پروژه است و نباید این مقادیر را داخل کد بنویسید.

1. در پروژه‌ی Apps Script، از نوار سمت چپ روی آیکون چرخ‌دنده کلیک کنید.
2. وارد بخش **Project Settings** شوید.
3. پایین صفحه بخش **Script Properties** را پیدا کنید.
4. روی **Add script property** کلیک کنید.
5. نام کلید را در ستون **Property** و مقدار آن را در ستون **Value** وارد کنید.
6. برای هر ردیف، دقیقاً از نام‌های زیر استفاده کنید؛ حروف بزرگ، زیرخط و املای نام مهم است.
7. پس از افزودن ردیف‌ها، روی **Save script properties** کلیک کنید.

### تنظیمات ضروری

| نام Property | مقدار | نمونه |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | توکن کامل BotFather | `123456789:AAExampleTokenValue` |
| `TELEGRAM_CHANNELS` | username کانال عمومی یا شناسه‌ی عددی کانال | `@my_news_channel` |

برای چند مقصد، شناسه‌ها را با کاما جدا کنید و بین آن‌ها توضیح اضافه ننویسید:

```text
@channel_one,@channel_two,-1001234567890
```

### تنظیمات Gemini و رفتار جایگزین

| نام Property | مقدار پیشنهادی | توضیح |
| --- | --- | --- |
| `GEMINI_API_KEY` | کلیدی که از Google AI Studio گرفتید | برای تولید عنوان، خلاصه و هشتگ. |
| `AI_MODEL` | `gemini-2.0-flash-lite` | اختیاری؛ اگر مطمئن نیستید همان مقدار پیش‌فرض را بگذارید یا وارد نکنید. |
| `OUTPUT_LANGUAGE` | `Persian` | زبان خروجی Gemini. |
| `ENABLE_AI_FALLBACK` | `true` | اگر Gemini در دسترس نبود، سیستم با متن خام ادامه می‌دهد. |

اگر کلید Gemini را وارد نکردید، فقط این مقدار را ثبت کنید:

```text
ENABLE_AI_FALLBACK=true
```

### تنظیمات اختیاری

| نام Property | مقدار و نمونه | کاربرد |
| --- | --- | --- |
| `BLOCKED_HASHTAGS` | `#تبلیغات, #نمونه` | این هشتگ‌ها قبل از ارسال از متن حذف می‌شوند؛ فاصله یا کاما مجاز است. |
| `TELEGRAM_CHANNELS_JSON` | `["@channel_one","-1001234567890"]` | جایگزین `TELEGRAM_CHANNELS` برای چند مقصد. اگر هر دو را ثبت کنید، این مقدار اولویت دارد. |
| `SOURCES_JSON` | آرایه‌ی JSON منابع | جایگزین کامل منابع پیش‌فرض. در مرحله‌ی بعد توضیح داده شده است. |

نمونه‌ی تنظیمات متنی؛ این را به‌عنوان یک Property واحد وارد نکنید، بلکه هر خط را در ردیف جداگانه قرار دهید:

```text
TELEGRAM_BOT_TOKEN=توکن واقعی ربات
TELEGRAM_CHANNELS=@نام_کانال
GEMINI_API_KEY=کلید واقعی Gemini
AI_MODEL=gemini-2.0-flash-lite
OUTPUT_LANGUAGE=Persian
ENABLE_AI_FALLBACK=true
```

## مرحله‌ی ۶: تنظیم منابع خبری

اگر `SOURCES_JSON` را تنظیم نکنید، سیستم از دو منبع پیش‌فرض تعریف‌شده در [`DEFAULT_SOURCES`](Code.gs:35) استفاده می‌کند. برای شروع می‌توانید این مرحله را رد کنید و ابتدا همان منابع پیش‌فرض را آزمایش کنید.

### RSS چیست و آدرس آن را از کجا پیدا کنیم؟

RSS یا Atom یک صفحه‌ی متنی/XML است که سایت‌ها برای اعلام مطالب جدید منتشر می‌کنند. آدرس آن معمولاً با یکی از این عبارت‌ها تمام می‌شود:

- `/feed`
- `/feed/`
- `/rss.xml`
- `/atom.xml`
- `/index.xml`

برای پیدا کردن آدرس:

1. نام سایت و عبارت `RSS feed` را جست‌وجو کنید.
2. در سایت به دنبال لینک یا آیکون RSS بگردید.
3. آدرس XML را در مرورگر باز کنید؛ اگر متنی شامل `<rss>`، `<feed>`، `<item>` یا `<entry>` دیدید، احتمالاً آدرس درست است.
4. صفحه‌ی عادی مقاله یا صفحه‌ی اصلی سایت را به‌جای آدرس RSS وارد نکنید.

نمونه‌ی یک منبع RSS:

```json
[
  {
    "id": "my-site",
    "type": "rss",
    "name": "نام سایت",
    "feedUrl": "https://example.com/feed.xml",
    "category": "technology",
    "headlinePrefix": "خبر فناوری",
    "fixedTags": "#فناوری #خبر",
    "maxPostsPerRun": 2
  }
]
```

### منبع GitHub

برای دریافت پروژه‌های محبوب GitHub از این شکل استفاده کنید:

```json
[
  {
    "id": "github-trending",
    "type": "github",
    "name": "GitHub Trending",
    "trendingUrl": "https://github.com/trending?since=daily",
    "category": "development",
    "headlinePrefix": "پروژه‌ی محبوب گیت‌هاب",
    "fixedTags": "#گیتهاب #برنامه_نویسی",
    "maxPostsPerRun": 2
  }
]
```

### منبع ترکیبی

اگر چند منبع می‌خواهید، همه را داخل یک آرایه قرار دهید:

```json
[
  {
    "id": "security-feed",
    "type": "rss",
    "name": "Security feed",
    "feedUrl": "https://example.com/security.xml",
    "category": "security",
    "headlinePrefix": "امنیت سایبری",
    "fixedTags": "#امنیت",
    "maxPostsPerRun": 3
  },
  {
    "id": "github-trending",
    "type": "github",
    "name": "GitHub Trending",
    "trendingUrl": "https://github.com/trending?since=daily",
    "category": "development",
    "headlinePrefix": "پروژه‌ی محبوب گیت‌هاب",
    "fixedTags": "#گیتهاب",
    "maxPostsPerRun": 2
  }
]
```

این JSON را به‌عنوان مقدار یک Property با نام `SOURCES_JSON` وارد کنید. JSON باید یک خطا نداشته باشد: کامای اضافی انتهای آخرین فیلد، کوتیشن‌های فارسی یا کامای بین دو منبع اشتباه باعث خطا می‌شود. در صورت نیاز JSON را قبل از ثبت در یک JSON validator بررسی کنید.

فیلدهای منبع:

| فیلد | توضیح |
| --- | --- |
| `id` | شناسه‌ی یکتا و انگلیسی منبع؛ مثلاً `security-feed`. تغییر آن تاریخچه‌ی قبلی را بی‌اثر می‌کند. |
| `type` | `rss` یا `github`. برای فیدهای RSS/Atom مقدار `rss` است. |
| `name` | نام قابل نمایش منبع. |
| `feedUrl` | آدرس مستقیم فید RSS/Atom. برای `rss` ضروری است. |
| `trendingUrl` | آدرس صفحه‌ی Trending. برای `github` ضروری است. |
| `category` | یکی از `security`، `development`، `technology` یا `general`. |
| `headlinePrefix` | متنی که ابتدای پیام تلگرام نمایش داده می‌شود. |
| `fixedTags` | هشتگ‌های ثابت، مانند `#فناوری`. |
| `maxPostsPerRun` | سقف پیام آن منبع در یک اجرا؛ سقف کلی سیستم ۳ پیام است. |

در هر اجرای ساعتی، یک منبع انتخاب می‌شود. اگر چند منبع دارید، در اجراهای بعدی به‌صورت چرخشی بررسی می‌شوند.

## مرحله‌ی ۷: اجرای اول و دادن مجوز به Google

قبل از اجرای اول، مطمئن شوید کد ذخیره شده و Script Properties را ثبت کرده‌اید.

1. بالای ویرایشگر Apps Script، از فهرست انتخاب تابع، [`testTelegramChannels()`](Code.gs:160) را انتخاب کنید.
2. روی **Run** کلیک کنید.
3. Google احتمالاً پنجره‌ی **Authorization required** نشان می‌دهد؛ روی **Review permissions** کلیک کنید.
4. حساب Google خود را انتخاب کنید.
5. اگر صفحه‌ای با عنوان **This app isn’t verified** دیدید، این هشدار به‌دلیل شخصی بودن اسکریپت است:
   - روی **Advanced** کلیک کنید.
   - روی **Go to ContentFlow-AI (unsafe)** یا نام پروژه‌ی خودتان کلیک کنید.
   - مجوزها را بررسی و روی **Allow** کلیک کنید.
6. چند ثانیه صبر کنید تا اجرا تمام شود.
7. در کانال بررسی کنید پیام آزمایشی با متن `Test message` دریافت شده باشد.

این اسکریپت فقط پروژه‌ی خودتان است؛ هشدار تأییدنشده‌بودن به معنی خراب‌بودن کد نیست. اگر از حساب سازمانی استفاده می‌کنید و گزینه‌ی ادامه نمایش داده نمی‌شود، باید مدیر سازمان مجوز اجرای Apps Script را فعال کند.

## مرحله‌ی ۸: آزمایش منبع و ارسال واقعی

### آزمایش اتصال به تلگرام

تابع [`testTelegramChannels()`](Code.gs:160) فقط برای بررسی تنظیمات مقصد است. اجرای آن باید در همه‌ی کانال‌های ثبت‌شده پیام آزمایشی ایجاد کند.

### آزمایش دریافت یک منبع

1. مقدار `id` یک منبع را از `SOURCES_JSON` یا [`DEFAULT_SOURCES`](Code.gs:35) پیدا کنید.
2. تابع [`testSource('security-feed')`](Code.gs:159) را انتخاب کنید.
3. مقدار داخل کوتیشن را با شناسه‌ی واقعی عوض کنید؛ مثلاً `github-trending`.
4. روی **Run** کلیک کنید.
5. در بخش **Execution log** یا **Logs** بررسی کنید که عنوان، لینک و توضیح چند مطلب نمایش داده شده باشد.

این تابع مطلبی را در تلگرام منتشر نمی‌کند؛ فقط اتصال و دریافت منبع را آزمایش می‌کند.

### اجرای کامل یک چرخه

تابع [`testScheduler()`](Code.gs:158) یک اجرای واقعی سیستم را شبیه‌سازی می‌کند. ممکن است تا ۳ پیام در کانال منتشر کند. بهتر است این تابع را فقط پس از موفقیت آزمایش تلگرام و منبع اجرا کنید.

اگر پیام دریافت نشد، بخش [خطاهای رایج](#خطاهای-رایج) را بررسی کنید و همچنین صفحه‌ی **Executions** را ببینید.

## مرحله‌ی ۹: زمان‌بندی اجرای خودکار در Google Apps Script

### Trigger چیست؟

Trigger یا «راه‌انداز» به Google Apps Script می‌گوید یک تابع را بدون کلیک دستی و در زمان مشخص اجرا کند. در این پروژه تابعی که باید زمان‌بندی شود [`scheduler()`](Code.gs:58) است. این تابع هر بار:

1. تنظیمات و کلیدهای لازم را می‌خواند.
2. از بین منابع، یک منبع را انتخاب می‌کند.
3. مطالب جدید و غیرتکراری را پیدا می‌کند.
4. در صورت فعال بودن Gemini، متن را تولید می‌کند.
5. حداکثر ۳ پیام را به تلگرام می‌فرستد.
6. تاریخچه‌ی لینک‌ها و ارسال‌ها را ذخیره می‌کند.

اجرای دستی [`testScheduler()`](Code.gs:158) فقط برای آزمایش است و خودش زمان‌بندی دائمی ایجاد نمی‌کند. زمان‌بندی واقعی فقط با Trigger انجام می‌شود.

### روش ساده: ساخت Trigger ساعتی با `setupTrigger()`

این روش برای بیشتر کاربران پیشنهاد می‌شود و فقط یک‌بار لازم است:

1. مطمئن شوید [`testTelegramChannels()`](Code.gs:160) و [`testScheduler()`](Code.gs:158) بدون خطا اجرا شده‌اند.
2. در بالای ویرایشگر Apps Script، از فهرست تابع‌ها، [`setupTrigger()`](Code.gs:157) را انتخاب کنید.
3. روی **Run** کلیک کنید.
4. اگر Google پنجره‌ی مجوز نشان داد، همان مراحل **Review permissions → انتخاب حساب → Allow** را انجام دهید.
5. تابع `setupTrigger` ابتدا Triggerهای قبلی همین پروژه را که تابعشان `scheduler` است حذف می‌کند و سپس یک Trigger جدید می‌سازد.
6. این Trigger با [`everyHours(1)`](Code.gs:157) تنظیم شده است؛ یعنی تابع `scheduler` تقریباً هر ساعت یک‌بار اجرا می‌شود.

> اگر `setupTrigger()` را چند بار اجرا کنید، به‌دلیل حذف Triggerهای قبلی، چند اجرای موازی برای `scheduler` ساخته نمی‌شود. بااین‌حال بهتر است آن را فقط هنگام نصب اولیه یا تغییر زمان‌بندی اجرا کنید.

### بررسی اینکه Trigger ساخته شده است

1. در نوار سمت چپ Apps Script روی آیکون ساعت یا **Triggers** کلیک کنید.
2. باید یک ردیف برای تابع `scheduler` ببینید.
3. در ستون‌ها بررسی کنید:
   - **Function**: `scheduler`
   - **Event source**: `Time-driven`
   - **Type of time based trigger**: اجرای ساعتی یا **Hour timer**
   - **Owner**: حساب Google شما
4. اگر ردیفی وجود ندارد، `setupTrigger()` را دوباره اجرا کنید و صفحه را refresh کنید.

### روش دستی: ساخت Trigger از رابط کاربری

اگر می‌خواهید زمان‌بندی دیگری داشته باشید یا نمی‌خواهید `setupTrigger()` را اجرا کنید:

1. از نوار سمت چپ روی **Triggers** کلیک کنید.
2. روی **Add Trigger** در پایین صفحه کلیک کنید.
3. در بخش **Choose which function to run**، تابع `scheduler` را انتخاب کنید؛ `testScheduler` را انتخاب نکنید.
4. در **Choose which deployment should run**، گزینه‌ی **Head** یا deployment پیش‌فرض پروژه را انتخاب کنید.
5. در **Select event source**، گزینه‌ی **Time-driven** را انتخاب کنید.
6. در بخش نوع زمان‌بندی، یکی از گزینه‌ها را انتخاب کنید:
   - **Hour timer**: اجرا در بازه‌های ساعتی؛ برای این پروژه گزینه‌ی مناسب است.
   - **Day timer**: یک‌بار در روز، در بازه‌ی ساعتی که انتخاب می‌کنید.
   - **Week timer**: در یک روز مشخص هفته و یک بازه‌ی ساعتی.
   - **Month timer**: یک‌بار در ماه، در بازه‌ی انتخاب‌شده.
7. بازه‌ی موردنظر را انتخاب کنید؛ مثلاً **Every hour** یا **Every 2 hours**.
8. در قسمت **Failure notification settings** گزینه‌ی ارسال اعلان خطا را فعال کنید؛ مثلاً اعلان روزانه یا هفتگی.
9. روی **Save** کلیک کنید.

اگر قبلاً با `setupTrigger()` Trigger ساخته‌اید و سپس از رابط کاربری یک Trigger دیگر بسازید، ممکن است دو اجرای مستقل داشته باشید. در صفحه‌ی **Triggers** فقط یک ردیف برای `scheduler` نگه دارید، مگر اینکه عمداً چند زمان‌بندی متفاوت می‌خواهید.

### منطقه‌ی زمانی و ساعت اجرای واقعی

زمان‌بندی‌های Google Apps Script بر اساس منطقه‌ی زمانی پروژه کار می‌کنند، نه لزوماً ساعت کامپیوتر شما.

برای بررسی یا تغییر منطقه‌ی زمانی:

1. در Apps Script روی آیکون چرخ‌دنده و سپس **Project Settings** کلیک کنید.
2. بخش **Time zone** را پیدا کنید.
3. منطقه‌ی زمانی مناسب را انتخاب کنید؛ مثلاً `Asia/Tehran` برای ایران یا منطقه‌ی موردنظر خودتان.
4. پروژه را ذخیره کنید.
5. اگر Trigger روزانه، هفتگی یا ماهانه دارید، بعد از تغییر منطقه‌ی زمانی زمان اجرای آن را دوباره بررسی کنید.

Google معمولاً Trigger را دقیقاً در دقیقه‌ی مشخص اجرا نمی‌کند و آن را در یک بازه‌ی زمانی اجرا می‌کند. برای مثال، «هر ساعت» به معنی اجرای تقریبی ساعتی است، نه تضمین اجرای دقیق در دقیقه‌ی صفر. خاموش بودن کامپیوتر اهمیتی ندارد؛ Trigger روی سرورهای Google اجرا می‌شود.

### رفتار زمان‌بندی با چند منبع

در هر اجرای `scheduler` فقط یک منبع انتخاب می‌شود. انتخاب منبع با تابع [`getSourceForCurrentHour()`](Code.gs:84) بر اساس ساعت فعلی و تعداد منابع انجام می‌شود؛ بنابراین اگر ۳ منبع داشته باشید، اجراهای ساعتی تقریباً به‌صورت چرخشی بین آن‌ها تقسیم می‌شوند.

مثلاً با سه منبع:

- اجرای اول: منبع اول
- اجرای بعدی: منبع دوم
- اجرای بعدی: منبع سوم
- اجرای بعدی: دوباره منبع اول

به همین دلیل، اگر می‌خواهید همه‌ی منابع در هر ساعت بررسی شوند، این نسخه‌ی کد برای آن طراحی نشده است. راه ساده‌تر این است که برای هر منبع پروژه یا تابع زمان‌بندی جداگانه داشته باشید؛ اما این کار نیازمند تغییر کد است. در حالت عادی همان یک Trigger ساعتی را نگه دارید.

### سرعت، محدودیت و جلوگیری از اجرای هم‌زمان

- در هر اجرای زمان‌بندی‌شده حداکثر ۳ پیام ارسال می‌شود؛ مقدار `maxPostsPerRun` منبع نمی‌تواند از این سقف کلی عبور کند.
- برای جلوگیری از فشار به Telegram، بین ارسال چند پیام مکث کوتاه وجود دارد.
- [`LockService`](Code.gs:59) از اجرای هم‌زمان دو چرخه جلوگیری می‌کند؛ اگر یک اجرا هنوز تمام نشده باشد، اجرای هم‌زمان جدید کنار گذاشته می‌شود.
- Google Apps Script سهمیه‌ی روزانه و محدودیت زمان اجرای هر پروژه دارد. اگر تعداد منابع، پیام‌ها یا درخواست‌های Gemini زیاد شود، ممکن است اجرای پروژه به سهمیه برسد.
- Triggerهای خیلی پرتعداد نسازید؛ برای شروع یک Trigger ساعتی کافی است.

### دیدن اجرای موفق یا خطادار

1. در منوی سمت چپ Apps Script روی **Executions** کلیک کنید.
2. هر ردیف یک اجرای دستی یا زمان‌بندی‌شده است.
3. در ستون تابع باید `scheduler`، و در ستون شروع باید زمان اجرای Trigger را ببینید.
4. اجرای موفق معمولاً وضعیت **Completed** دارد.
5. اجرای ناموفق وضعیت **Failed** دارد؛ روی آن کلیک کنید تا پیام خطا، زمان و جزئیات نمایش داده شود.
6. اگر خطا مربوط به توکن، کانال یا Gemini است، مقدار Script Properties و عضویت ربات در کانال را بررسی کنید.
7. پس از اصلاح تنظیمات، لازم نیست Trigger را حذف کنید؛ اجرای بعدی به‌صورت خودکار با تنظیمات جدید انجام می‌شود.

### اگر Trigger اجرا نمی‌شود

این موارد را به‌ترتیب بررسی کنید:

1. در صفحه‌ی **Triggers** وجود یک Trigger برای `scheduler` را بررسی کنید.
2. مطمئن شوید Trigger روی `scheduler` است، نه `setupTrigger` یا `testScheduler`.
3. در **Executions** بررسی کنید اجرا انجام شده اما خطا داده است.
4. در **Project Settings → Script Properties** وجود `TELEGRAM_BOT_TOKEN` و مقصد تلگرام را بررسی کنید.
5. اگر به‌تازگی مجوزها را تغییر داده‌اید، یک بار [`testScheduler()`](Code.gs:158) را دستی اجرا کنید تا Google مجوزهای لازم را دوباره بگیرد.
6. اگر Trigger صاحب دیگری دارد، با همان حساب Google وارد شوید یا Trigger را حذف و با حساب صحیح دوباره بسازید.
7. اگر پروژه به سقف سهمیه رسیده باشد، در صفحه‌ی **Executions** یا اعلان‌های Google خطای quota دیده می‌شود؛ تعداد اجراها و منابع را کاهش دهید.
8. اگر هیچ خطایی وجود ندارد اما پیام جدیدی ارسال نمی‌شود، احتمالاً مطلبی در ۴۸ ساعت اخیر پیدا نشده یا لینک‌ها قبلاً در تاریخچه ثبت شده‌اند.

### حذف یا تغییر Trigger

برای حذف زمان‌بندی:

1. به بخش **Triggers** بروید.
2. ردیف مربوط به `scheduler` را پیدا کنید.
3. روی منوی سه‌نقطه یا آیکون حذف همان ردیف کلیک کنید.
4. حذف را تأیید کنید.

برای تغییر زمان‌بندی، می‌توانید Trigger قبلی را حذف و یک Trigger جدید بسازید. اگر فقط می‌خواهید همان Trigger ساعتی پروژه دوباره ساخته شود، [`setupTrigger()`](Code.gs:157) را اجرا کنید؛ این تابع Triggerهای قبلی `scheduler` را پاک و یک Trigger ساعتی تازه ایجاد می‌کند.

Trigger با حساب Google مالک پروژه اجرا می‌شود. اگر مالکیت پروژه، حساب Google، مجوزهای API یا Script Properties تغییر کند، زمان‌بندی را دوباره در صفحه‌ی **Triggers** و **Executions** بررسی کنید.

## قالب پیام خروجی

هر پیام شامل این موارد است:

- پیشوند و عنوان مطلب.
- خلاصه‌ی تولیدشده توسط Gemini یا متن خام منبع.
- نام منبع و لینک مطلب اصلی.
- هشتگ‌های ثابت منبع و هشتگ‌های تولیدشده.

پیام با قالب HTML تلگرام ارسال می‌شود و متن‌های خارجی قبل از ارسال پاک‌سازی و escape می‌شوند. این نسخه تصویر مطلب را دریافت نمی‌کند و پیام متنی می‌فرستد.

## جلوگیری از انتشار تکراری

- لینک‌های دیده‌شده‌ی هر منبع در کلیدی مانند `SEEN_<source-id>` ذخیره می‌شوند.
- عنوان‌های اخیر در `RECENT_TITLES` ذخیره می‌شوند.
- عنوان‌هایی که بیش از حد به عنوان‌های اخیر شبیه باشند، با آستانه‌ی `0.82` کنار گذاشته می‌شوند.
- رسید ارسال موفق هر کانال در کلیدهایی با پیشوند `TELEGRAM_SENT_` ذخیره می‌شود.
- فقط مطالب حداکثر ۴۸ ساعت اخیر بررسی می‌شوند.
- در هر اجرا حداکثر ۳ پیام ارسال می‌شود.

برای پاک‌کردن تاریخچه و شروع آزمایش از ابتدا، تابع [`resetNewsHistory()`](Code.gs:162) را اجرا کنید. این کار باعث می‌شود مطالب قبلی دوباره قابل انتخاب شوند؛ بنابراین آن را در محیط واقعی با احتیاط اجرا کنید.

## شخصی‌سازی زبان و متن هوش مصنوعی

قواعد Gemini در شیء [`PROMPTS`](Code.gs:5) قرار دارند. برای تغییر لحن، قواعد محتوا، دسته‌بندی‌ها یا توضیح منابع GitHub، همین بخش را ویرایش کنید. برای تغییر فقط زبان، مقدار `OUTPUT_LANGUAGE` را در Script Properties تغییر دهید؛ مثلاً `English` یا `Persian`.

وقتی `GEMINI_API_KEY` وجود داشته باشد، مطالب انتخاب‌شده در یک درخواست batch برای Gemini ارسال می‌شوند. اگر Gemini خطا بدهد و `ENABLE_AI_FALLBACK=true` باشد، سیستم از عنوان و توضیح خام استفاده می‌کند. اگر می‌خواهید خطای Gemini باعث توقف اجرا شود، مقدار fallback را `false` کنید.

## امنیت و نگهداری

- توکن `TELEGRAM_BOT_TOKEN` و `GEMINI_API_KEY` را هرگز در [`Code.gs`](Code.gs)، [`README.md`](README.md)، GitHub یا اسکرین‌شات عمومی قرار ندهید.
- اگر توکن BotFather فاش شد، فوراً با BotFather آن را revoke و جایگزین کنید.
- کلید Gemini را با شخص دیگری به اشتراک نگذارید و مصرف آن را در Google AI Studio بررسی کنید.
- `SOURCES_JSON` ممکن است شامل URLهای خصوصی باشد؛ آن را هم در مخزن عمومی قرار ندهید.
- تابع [`debugBotState()`](Code.gs:161) مقادیر حساس دارای نام‌هایی مانند `TOKEN` و `KEY` را mask می‌کند، اما خروجی log را عمومی نکنید.
- تابع [`resetNewsHistory()`](Code.gs:162) داده‌های تاریخچه را پاک می‌کند و ممکن است باعث انتشار دوباره شود.
- اگر پروژه را به فرد دیگری منتقل می‌کنید، مالکیت پروژه، Script Properties و Triggerها را جداگانه بررسی کنید.

## خطاهای رایج

| خطا یا وضعیت | راه‌حل ساده |
| --- | --- |
| `TELEGRAM_BOT_TOKEN is missing` | در **Project Settings → Script Properties** ردیفی با نام دقیق `TELEGRAM_BOT_TOKEN` بسازید و توکن BotFather را در مقدار آن قرار دهید. |
| `Set TELEGRAM_CHANNELS or TELEGRAM_CHANNELS_JSON` | یکی از این دو Property را بسازید و username یا شناسه‌ی عددی کانال را وارد کنید. |
| `Telegram delivery incomplete` | ربات را Administrator کانال کنید، مجوز ارسال پیام بدهید و شناسه‌ی کانال را بررسی کنید. |
| پیام آزمایشی نمی‌آید | ابتدا مطمئن شوید ربات در کانال است؛ سپس توکن و شناسه را دوباره کپی کنید و `testTelegramChannels()` را اجرا کنید. |
| `GEMINI_API_KEY is missing and fallback is disabled` | کلید Gemini را ثبت کنید یا `ENABLE_AI_FALLBACK` را `true` کنید. |
| `SOURCES_JSON is not valid JSON` | براکت‌ها، کوتیشن‌های انگلیسی، کاماها و ساختار آرایه را بررسی کنید. |
| `Source not found` | مقدار داخل `testSource()` باید دقیقاً با `id` یکی از منابع برابر باشد. |
| منبع پیام ندارد | آدرس فید، قدیمی‌بودن مطالب، تکراری‌بودن لینک و سقف `maxPostsPerRun` را بررسی کنید. |
| هیچ اجرای خودکاری دیده نمی‌شود | بخش **Triggers** و سپس **Executions** را باز کنید و مطمئن شوید Trigger برای `scheduler` وجود دارد. |
| خطای مجوز Google | با حساب مالک پروژه وارد شوید و اجرای تابع را دوباره تأیید کنید؛ در حساب سازمانی از مدیر کمک بگیرید. |
| عنوان تکراری رد می‌شود | این رفتار عمدی است؛ در صورت نیاز [`resetNewsHistory()`](Code.gs:162) را اجرا کنید. |
